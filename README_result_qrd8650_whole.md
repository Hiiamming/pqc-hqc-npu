## HQC-192 Scaling Investigation

The HQC-192 result is repeatable and is not a single qprof outlier. Direct
reruns without qprof on QRD8650 gave:

| HQC | CPU scalar direct rerun us/decode | NPU FastRPC direct rerun us/decode |
| --- | ---: | ---: |
| 128 | 71.505 / 71.508 / 71.482 | 47.766 / 47.756 / 47.803 |
| 192 | 92.266 / 92.278 / 92.342 | 106.550 / 106.508 / 106.737 |
| 256 | 202.058 / 202.030 / 203.999 | 165.896 / 165.898 / 165.916 |

The main reason HQC-192 does not scale smoothly is that the intrinsic RM path
changes shape after HQC-128:

- HQC-128 has `PARAM_N1=46`, `PARAM_N2=384`, so RM multiplicity is 3. The
  intrinsic code uses a dedicated 3-copy nibble LUT path.
- HQC-192 has `PARAM_N1=56`, `PARAM_N2=640`, so RM multiplicity is 5. It leaves
  the 3-copy LUT path and uses the generic 5-copy arithmetic expansion path.
- HQC-256 also uses multiplicity 5, but has `PARAM_N1=90`, so the larger total
  workload gives the cDSP/HVX path more room to amortize fixed FastRPC/runtime
  overhead and to beat the CPU scalar baseline.

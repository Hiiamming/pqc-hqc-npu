## Direct Energy Aggregate

How this table is measured:

- Workload: each row runs the full decode benchmark on device. CPU rows run the ARM64 scalar binary; NPU rows run the non-worker `labs/fastest` FastRPC binary.
- Repeat count: `n` is the number of measured repeats used for mean/std/variance.
- Timing source: benchmark stdout reports elapsed time and total decodes; `us mean = elapsed_us / total_decodes`, `dec/s mean = total_decodes / elapsed_s`.
- Energy source: `scripts/measure_board_energy.sh` samples Android power-supply voltage/current while the workload runs, with idle sampled before/after the workload.
- `delta W`: active average board power minus idle average board power.
- `uJ`: energy per decode, computed as `delta_W * elapsed_s / total_decodes * 1e6`.
- `dec/s/W`: throughput per watt, computed as `decodes_per_s / delta_W`.
- `speedup`: CPU `us/decode` divided by NPU `us/decode` for the same HQC level. CPU baseline is fixed to `1`.
- `energy gain`: CPU `uJ/decode` divided by NPU `uJ/decode` for the same HQC level. CPU baseline is fixed to `1`.
- Per-row workload size: each repeat decodes all `256` fixtures for `125` iterations, so `total_decodes=32000` for every row.
- Direct-energy sampling parameters: `SAMPLE_INTERVAL=0.1`, `IDLE_SECONDS=10`, `IDLE_POSITION=both`; raw sample counts are retained in each repeat's `summary.env`.
- `std` is sample standard deviation over repeats. `var` is `std^2`.

## Process CPU Aggregate

How this table is measured:

- Workload: same decode binaries as the direct energy table, but wrapped by `scripts/measure_process_cpu.sh`.
- Source: the script samples per-thread CPU ticks from `/proc/<pid>/task/*/stat` while the process is alive.
- Per-row workload size: same `256` fixtures, `125` iterations, and `32000` total decodes as the direct-energy table.
- Process sampler interval: `PROCESS_CPU_SAMPLE_INTERVAL=0.02`; Android `CLK_TCK` was read from the run summaries and CPU seconds are derived from process tick deltas.
- `process CPU mean %`: process CPU time consumed during the wall-clock interval, normalized by elapsed wall time. Roughly, `100%` means one CPU core fully busy.
- `CPU ms/decode`: process CPU milliseconds divided by total decodes. This is CPU work spent by the process, not wall latency.
- `CPU reduction %`: how much less process CPU time the NPU row uses versus CPU scalar for the same HQC level: `(1 - npu_cpu_ms_per_decode / cpu_cpu_ms_per_decode) * 100`.
- `std` is sample standard deviation over repeats. `var` is `std^2`.

Notes:

- Workload: `scripts/measure_android_fastrpc_overhead.sh` builds the same FastRPC host/skel, pushes it to the device, then calls special `hqc_host` modes.
- Fixture correction: the HQC-192/HQC-256 `bench` and `decode_one` rows below were measured before the full-RM-block fixture injection fix. Treat those decode rows as superseded until rerun. Non-decode boundary rows (`ping`, `open_close`, payload probes) are not affected by the RS fixture contents.
- Build/run parameters: `LEVELS="128 192 256"`, `REPEATS=5`, `HEXAGON_ARCH=v73`, `PING_CALLS=10000`, `OPEN_CLOSE_CALLS=100`, `PAYLOAD_CALLS=10000`, `DECODE_ONE_CALLS=10000`, and `BENCH_ITERS=125`.
- Fixture parameters for decode modes: same generated corpus as above, `256` fixtures per HQC level, default fixture seed `0x128c0de5`, and RS-symbol error schedule `fixture_index % (PARAM_DELTA + 1)`.
- `bench` mode decode count: `BENCH_ITERS * fixture_count = 125 * 256 = 32000` decodes per repeat.
- `decode_one` mode decode count: `10000` independent one-decode RPC calls per repeat. The DSP advances an internal fixture index by one call and wraps modulo `256`, so each repeat cycles through the same fixture corpus about `39` full times plus `16` fixtures.
- All rows below are microseconds per RPC/call, except `bench` which is microseconds per decode in batched mode.
- `ping`: empty/lightweight RPC call. This approximates the base FastRPC call boundary cost.
- `open_close`: repeatedly opens/closes the FastRPC session. This is setup/teardown overhead, not per-decode steady-state cost.
- `payload_in_*`: sends an input buffer from CPU to DSP. The input size is HQC codeword size: 2304 bytes for 128, 4480 for 192, 7296 for 256.
- `payload_out_*`: receives a 128-byte output buffer from DSP to CPU.
- `payload_inout_*`: sends the HQC-sized input buffer and receives the 128-byte output buffer in the same RPC.
- Payload probe sizes are synthetic FastRPC transfer sizes from `run.info`: input payloads are `2304`, `4480`, and `7296` bytes for HQC-128/192/256, and output payloads are `128` bytes for all levels. These payload sizes are not the same field as the compiled decode fixture array size for HQC-128 and HQC-256.
- `malloc`: normal host allocation. `rpcmem-cached` and `rpcmem-uncached`: buffers allocated through rpcmem with cached/uncached mapping.
- `decode_one`: one decode per RPC call, so this includes FastRPC boundary overhead on every decode.
- `bench`: batched decode path with `BENCH_ITERS=125`, so one host run performs 32000 decodes and amortizes the boundary overhead.
- `std` is sample standard deviation over repeats. `variance` is `std^2`.
- A partial default-call-count run at `results/fastrpc_overhead/20260529_232629_hqc128` was stopped because it was too slow; it is not included here.
- Raw dirs: `results/fastrpc_overhead/20260529_232911_hqc128`, `results/fastrpc_overhead/20260529_233711_hqc192`, `results/fastrpc_overhead/20260529_234515_hqc256`.

## Simulator Full Decode and Selected Substage, Paired i1/i3

Generated by:

```sh
for variant in scalar fastest; do
  for level in 128 192 256; do
    scripts/sim_decode.sh --variant "$variant" --level "$level" --bench decode --iters 1
    scripts/sim_decode.sh --variant "$variant" --level "$level" --bench decode --iters 3
  done
done

for variant in scalar fastest; do
  for substage in 2 3 4 5; do
    scripts/sim_decode.sh --variant "$variant" --level 128 --bench substage --substage "$substage" --iters 1
    scripts/sim_decode.sh --variant "$variant" --level 128 --bench substage --substage "$substage" --iters 3
  done
done
```

Notes:

- Workload: Hexagon simulator only. No real-device latency or energy is measured here.
- Fixture corpus: current generated corpus, `256` fixtures per HQC level.
- Fixture generator and seed: `shared/tools/gen_hqc{1,3,5}_decode_fixture.c` with default `HQC_FIXTURE_SEED=0x128c0de5` unless the environment overrides it.
- Fixture contents: each fixture stores original message bytes, encoded/error-injected codeword bytes, expected recovered message bytes, and `rs_symbol_errors`.
- Fixture error schedule: fixture index `i` uses `i % (PARAM_DELTA + 1)` RS-symbol errors. `PARAM_DELTA` is `15` for HQC-128, `16` for HQC-192, and `29` for HQC-256.
- Decode fixture dimensions: message bytes are `16/24/32` for HQC-128/192/256; codeword bytes are `2208/4480/7200`; RS block counts `PARAM_N1` are `46/56/90`.
- Full-decode run matrix: variants `scalar` and `fastest`, levels `128 192 256`, and paired `--iters 1` plus `--iters 3`.
- Substage run matrix: variants `scalar` and `fastest`, HQC-128 only, substages `2 3 4 5`, and paired `--iters 1` plus `--iters 3`.
- Repeat count: single paired run. No mean/std/variance is reported for this simulator block.
- Source: `hexagon-sim` final `Total: Insns=... Pcycles=...` line, plus benchmark stdout lines `[decode-bench]` and `[substage-bench]`.
- `i1 Pcycles`: total processor cycles reported by `hexagon-sim` for `--iters 1`. This includes simulator/startup/setup overhead plus one pass over all fixtures.
- `i3 Pcycles`: total processor cycles reported by `hexagon-sim` for `--iters 3`. This includes the same fixed overhead plus three passes over all fixtures.
- `Delta decodes`: `total_decodes_i3 - total_decodes_i1`. With 256 fixtures, this is `768 - 256 = 512` extra decodes.
- Full decode `Pcycles/decode`: the extra cycles for the two additional fixture passes, divided by the extra decode count:
  `Pcycles/decode = (Pcycles_i3 - Pcycles_i1) / (total_decodes_i3 - total_decodes_i1)`.
  This subtracts most fixed simulator/startup/setup overhead instead of using raw `Pcycles / total_decodes`.
- `Insns/decode`: same idea as `Pcycles/decode`, but using simulator instruction count:
  `(Insns_i3 - Insns_i1) / (total_decodes_i3 - total_decodes_i1)`.
- `Delta ops`: `total_ops_i3 - total_ops_i1` for the substage benchmark. RM substages do one op per RM block; RS substages do one op per decode.
- RM substage op count: HQC-128 has `PARAM_N1=46` RM blocks per fixture, so one iteration has `256 * 46 = 11776` RM ops and the paired i1/i3 delta is `2 * 11776 = 23552` ops.
- RS substage op count: one RS op per fixture/decode, so one iteration has `256` RS ops and the paired i1/i3 delta is `2 * 256 = 512` ops.
- Substage `Pcycles/op`: `(Pcycles_i3 - Pcycles_i1) / Delta ops`.
- Substage `Pcycles/decode`: for RM substages, `Pcycles/op * 46` because HQC-128 has 46 Reed-Muller blocks per decode; for RS substages, `Pcycles/op` is already per decode.
- `speedup vs scalar`: scalar `Pcycles/decode` divided by fastest `Pcycles/decode` for the same HQC level. Higher is better.
- `Status`: both the `iters=1` and `iters=3` runs must report `PASS`.
- Raw dir: `results/sim_decode/20260530_003807_paired_i1_i3`.

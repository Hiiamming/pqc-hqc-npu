## Process CPU Offload Results

### Methodology

These rows measure CPU work consumed by the decoder process itself, not
whole-system CPU load. qprof `apps-proc-cpu-metrics` reports aggregate apps
processor load, so it can include Android background services, adb/qprof
overhead, thermal services, and unrelated work. It is diagnostic-only here and
is not used to quantify CPU offload.

For each workload, `measure_process_cpu.sh` launches the benchmark and samples
per-thread CPU ticks from:

```text
/proc/<pid>/task/*/stat
```

The process workload uses `exec ./binary ...`, so the measured PID is the
decoder binary itself: `hqc*_decode_bench_arm64_android` for CPU scalar and
`hqc_host` for NPU/FastRPC. The script records elapsed time, total decodes, and
process CPU ticks, then computes:

```text
process_cpu_s = delta(utime + stime ticks across all threads) / CLK_TCK
process_cpu_pct = 100 * process_cpu_s / elapsed_s
cpu_ms_per_decode = 1000 * process_cpu_s / total_decodes
reduction_vs_cpu = 100 * (cpu_ms_per_decode_cpu_scalar - cpu_ms_per_decode_backend)
                         / cpu_ms_per_decode_cpu_scalar
```

`CPU ms/decode` is the main offload metric because it normalizes host CPU work
by completed decodes, making faster NPU runs comparable with slower CPU scalar
runs.

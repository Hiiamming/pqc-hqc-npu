## qprof Setup

Status: qprof is available for diagnostic profiling.

Target files are installed with this layout:

- `QPROF_BIN=/vendor/bin/qprof`
- `QPROF_LIB_DIR=/vendor/qprof/libs`
- `QPROF_BACKEND_DIR=/vendor/qprof/backends`
- `ExtQProfiler.db` at `/data/shared/qcom/Shared/Prof_Ext/ExtQProfiler.db`

Every Android shell that runs qprof uses:

```sh
export QMONITOR_BACKEND_LIB_PATH=/vendor/qprof/backends
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/vendor/qprof/libs
```

Sanity check:

```sh
/vendor/bin/qprof --capabilities
```

The capabilities used for these measurements are:

- CPU: `profiler:apps-proc-cpu-metrics`
- Battery: `profiler:apps-proc-battery-metrics`
- Thermal: `profiler:apps-proc-thermal-metrics`
- NPU: `profiler:nsp1-dsp-metrics`

Device path uses Windows ADB through WSL:

```text
/mnt/c/Temp/ADB/platform-tools/adb.exe
```

Profiler settings:

- Direct energy source: Android power-supply voltage/current sampled by `measure_board_energy.sh`
- `DIRECT_SAMPLE_INTERVAL=0.1`
- `DIRECT_IDLE_SECONDS=10`
- `DIRECT_IDLE_POSITION=both`
- qprof context in the main direct-energy run: `RUN_QPROF_CONTEXT=0`
- qprof diagnostic rerun: `PROFILE_TIME=30`, `STREAMING_RATE=1000`, `SAMPLING_RATE=200`; HQC-256 NPU also has a `PROFILE_TIME=20` rerun because qprof 30s crashed after printing counters
- NPU profiler capability: `profiler:nsp1-dsp-metrics`
- CPU path: scalar ARM64 baseline built as an Android/Bionic PIE executable
- NPU path: current `hqc_lab_insintric` fastest non-CT FastRPC build flags (`HQC_RS_FAST_NON_CT=1`, `HQC_GF_LUT_MUL=1`, `HQC_RM_EXPAND_LUT=1`, `HQC_RM_FUSED_FAST=1`, `HQC_RS_ROOTS_HVX=1`)

Energy numbers in the main table use direct device power-supply samples with qprof disabled. qprof can perturb power and clock state, so qprof runs are diagnostic-only and are never mixed into the direct-energy table.
